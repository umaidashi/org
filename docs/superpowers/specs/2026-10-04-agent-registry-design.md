# 最初のe2e：Agentの登録と一覧表示

## 目的

AI Company Kernelを、小さな実際の動作を確かめながら育てる。最初の到達点は、登録したAgentを別のCLIプロセスから `org agent list` で確認できること。最終的には、小さなIssueをAgentに委譲し、実装・テスト・レビュー・Draft PRまで進められる基盤にする。

## 最初の範囲

- `org agent create cto --role CTO --runtime codex` でAgentを永続化する。
- `org agent list` でID、名前、役割、runtimeを表示する。
- `org agent list --json` で機械処理できるJSON配列を出力する。
- `org --db PATH ...` で保存先を指定できる。既定は `~/.local/share/org/org.db`。
- Agent IDはUUID。名前は一意で、重複登録は非ゼロ終了と明確なエラーにする。
- 名前・役割・runtimeは空文字を受け付けない。runtimeは実行機能のない識別文字列として保存する。
- 空の一覧は正常終了する。JSONでは `[]`、通常表示では未登録と分かるメッセージを出す。
- 一覧は名前の昇順とし、出力を安定させる。

## 実装方式

Python標準ライブラリのargparse・sqlite3・uuidを使う。依存パッケージを増やさず、SQLiteへの永続化を実際に検証できるため、この最初の範囲に向いている。CLI起動点を `org` にし、パッケージとしてインストールできるようにする。

代案はTypeScriptとSQLiteドライバ、またはJSONファイル保存。前者は現時点ではツールチェーンと依存を増やし、後者は予定しているSQLiteの永続化を検証できないため、今回はPythonとSQLiteを選ぶ。

CLIは引数・表示・終了コードを担当し、Agentの登録・取得は保存モジュールが担当する。SQLiteのスキーマにはID、名前、役割、runtime、作成日時を保持する。日時はUTC。SQLにはパラメータをバインドする。

CLIは保存先の親ディレクトリとDBを必要時に作る。保存失敗や重複は標準エラーへ報告し非ゼロ終了する。正常な一覧は標準出力へ出す。

## e2eと完了条件

一時ディレクトリのDBを指定し、実際のCLIを別プロセスとして起動する。

1. 未登録の一覧が正常終了しJSONで空配列になる。
2. CTOとChiefをそれぞれ登録できる。
3. 別プロセスから一覧を取得し、名前順・役割・runtime・安定したUUIDを確認できる。
4. 重複登録が失敗し、既存レコードが変わらない。
5. 通常表示でも登録済みAgentを確認できる。

READMEに導入方法・上記コマンド・e2e実行方法を載せる。この段階ではLLMや外部サービスを呼ばない。

## 次の検証単位

次はTaskの作成・取得・状態保存をCLIで一周させ、その後、一つのruntimeでTaskを実行して結果を保存する。各段階で別プロセスから状態が読めることを確かめる。daemon、Room、Memory、委譲、承認は、対応する実際の一周を作る段階で追加する。
