# typed A2Aの永続Message

目的：delegate/request/result/question/decision/blocker/cancelを自由文だけにせず、Roomの不変Messageへversion付きenvelopeとして保存する。宛先・Task・correlationを明示し、別CLIから参照する。

1. pure domainでtype/JSON payload/from/to/Room参加を検証。replyは同RoomのA2A Messageへ宛先を逆転し、correlationとTask参照を引き継ぐ。矛盾した指定を拒否。Room Messageの純粋生成でpayloadを複製する。RED→GREENのDB不要UT。
2. serviceへAgent/Room/Task PortとIdentityを注入。Agent存在・Task参照確認をappend前に行い、Room Adapterへ一度だけappendする。原本はRoom Message、別A2A tableとのdual writeを作らない。
3. `org a2a send ROOM --from AGENT --to AGENT --type TYPE --payload JSON [--task ID] [--correlation ID] [--reply-to ID]`とget/list。実daemon+SQLiteでrequest→resultとcorrelation/Task/履歴/再openを確認。全検査・実Jev・独立レビューを記録。

Review Focus: payloadのfinite JSON、sender/envelopeの一致、非参加Agent・別Room返信・Task/correlation取り違えを拒否。get/listはmetadata namespaceの未知/不正envelopeを成功として扱わない。認証されたAgent本人という保証、自動Task委譲、wake-up、外部A2A標準は後続。通常Room管理操作にも同OSユーザーの権限があるため、このAPIだけが原本の唯一の入力経路という認可保証はしない。
