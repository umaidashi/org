# Event・Subscriptionの検証単位

Notion「05｜Event・PubSub・Trigger」を再取得し、最終更新2026-10-04T01:51:58.336Zと照合。仕様の変更なし。

Eventは受信者を知らない不変の事実。Taskとは別のSQLite logへpublish/get/listする。Subscriptionはagent/workflow、対象ID、eventPattern、任意payload filter、enabledを保存する。CLIからpublish→別プロセス取得→Subscription照合→無効化→照合結果から除外するe2eをTDDで実装する。

Ruling: Eventにid/type/source/payload/createdAtを保持する。patternはdot区切り、`*`は1 segment、末尾`**`は0以上のsegment。filterはpayloadのトップレベルkeyのJSON値完全一致、objectのkey順序は無関係。filterなしは全payloadを受理。曖昧な正規表現や実行コードを受け取らない。

Agent購読はAgent Portで登録済みIDを確認する。Workflowはまだregistryがないため参照を保存するだけと明記し、実行はしない。照合は純粋関数。publish時にSubscription/Agentを参照しない。Event原本はUPDATE/DELETE triggerで保護する。Subscriptionの有効/無効を変更しても原本Eventを変更しない。

1. CLIの未実装RED。
2. pattern/filter/enabledの純粋UTをRED→GREEN。
3. 最小PortのDI、SQLite保存・不変原本・障害伝播のintegration。
4. CLI・全テスト・実jev・独立レビュー・ログを記録する。

daemonによるTask作成/Workflow起動、配信のidempotency/retryは次の実行検証単位に残す。この保存/照合e2eだけでPub/Sub全体完成とは扱わない。
