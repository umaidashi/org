# 方針
Task管理もProviderとして抽象化する。
CoreはLinearやGitHubのデータモデルを知らない。
```typescript
interface TaskProvider {
  create(task)
  get(id)
  update(id, patch)
  list(filter)
  addComment(id, comment)
  linkArtifact(id, artifact)
}
```
Adapter候補：
- LocalTaskProvider（SQLite/Postgres）
- LinearTaskProvider
- GitHubIssuesTaskProvider
- NotionTaskProvider
# Core Task model
```typescript
Task {
  id
  title
  objective
  status
  priority
  owner
  parentId?
  dependencies[]
  labels[]
  inputArtifacts[]
  outputArtifacts[]
  externalRef?
}
```
# WorkItemとExecutionTaskを分離
**WorkItem**
- 人間・PM向け
- Linear issue等と同期
- 比較的大きな成果単位
**ExecutionTask**
- Agentが内部で処理する細粒度Job
- Local storeに持つ
- 原則として外部タスク管理を汚さない
例：
```plain text
Linear Issue: 認証機能を実装
  ↓
Internal Execution Tasks
  ├─ schema調査
  ├─ backend実装
  ├─ test
  └─ review
```
# Task state
pending → assigned → running → blocked → waiting_approval → completed / failed
